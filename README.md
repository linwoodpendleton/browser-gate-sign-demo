# qlvm-demo — 浏览器环境门禁 + 每日字节码 VM 的签名方案(研究 demo)

> **⚠️ 仅限研究 / 教学用途。**
> 本仓库演示一种「只有真浏览器能算出有效签名、脚本算不出」的接口防刷思路。
> **生产环境请自行实现,请勿照抄本仓库任何代码。** 照抄明文 key、固定 env 清单、未混淆的
> 源码到线上 = 零防护。作者不对任何使用后果负责。

一句话:把接口签名用的 key 藏进一段**浏览器环境门禁**逻辑里 —— 真浏览器拿到真 key、脚本
拿到被污染的错 key;后端只做一次 HMAC 校验,**完全不关心环境**。再配合「每天轮换 key +
把门禁逻辑编成每日随机操作码的字节码 VM」,持续抬高逆向成本。

## 它解决什么

选品/比价这类接口常被 轮换 IP + `curl_cffi`/headless 脚本 高频刷。纯靠 IP 限流/UA 判断
很容易被绕。本方案的思路是让「签名能力」本身只存在于真浏览器里。

## 工作原理

```
          ┌─────────────── 浏览器 ───────────────┐
  请求体 →│ qlvm_source.js:env 门禁 → 门禁后的 key │
          │ qlcipher.js :HMAC(key, body|t|n|v)    │→ X-Ql-T/N/V/S 四个头
          └───────────────────────────────────────┘
                                │  body + 四个头
                                ▼
          ┌─────────────── 后端(Rust)─────────────┐
          │ 重算 HMAC(当天真 key, body|t|n|v) == S ? │ 对→放行  错/缺→拒
          └──────────────────────────────────────────┘
```

- **真浏览器**:env 全过 → mask=0 → key=真 key → 签名有效。
- **脚本(node/jsdom/headless/curl)**:env 某项失败 → key 被异或污染 → 签名无效。
- 后端无状态、不判断环境,只验 HMAC。协议细节见 [`docs/PROTOCOL.md`](docs/PROTOCOL.md)。

## 目录

```
frontend/
  qlvm_source.js   # env 门禁 → 返回门禁后的 key(demo:明文写死 key/date)
  qlcipher.js      # WebCrypto HMAC 签名 + 组头
  build.mjs        # (可选)每日字节码 VM 生成思路示意(需 js-confuser-vm)
  demo.html        # 浏览器里点一下看签名与后端响应
backend/           # Rust 验签后端(axum)
  src/main.rs
docs/PROTOCOL.md   # 请求头 / 签名拼接 / 验签流程 / 生产差异
```

## 快速跑通

**1. 启动后端**
```bash
cd backend
cargo run
# 监听 http://127.0.0.1:8080  (POST /getQueryList)
```

**2. 打开前端**(需用 http 协议打开,`file://` 下 WebCrypto 可能受限)
```bash
cd frontend
python3 -m http.server 5500
# 浏览器访问 http://127.0.0.1:5500/demo.html,点「签名并请求」
```

在真浏览器里应得到 `code: 0 (签名通过)`。若把同样的请求用 node/curl 手搓(env 门禁会给出
被污染的 key),后端会回 `请求校验失败`。

## 已知局限(这是 demo,不是产品)

- key、日期、env 清单全是明文/固定的,**没有混淆**。生产必须每日随机 + 编成字节码。
- 本 demo 的 env 检测清单与污染(扩散)算法是**特意挑的一套示意实现,与任何生产实现都不同**;
  它只传达思路,**挡不住**认真配置的 stealth 无头浏览器。具体检测项与污染算法请自行设计并保密,**勿照抄本仓库**。
- nonce 去重用进程内内存(重启失效、非分布式安全);生产用 Redis。
- 没有鉴权、限流、CORS 收敛、反调试等生产必需项。
- 真浏览器里跑一次就能读到当天真 key → 当天可廉价重放。本方案是「抬高成本 + 挡住纯脚本」,
  不是密码学意义上的不可破。
